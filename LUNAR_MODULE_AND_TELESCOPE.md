# Swapping in the Apollo 11 Lunar Module and the Spitzer Space Telescope

**Status (2026-11-15):**
- **Lunar Module:** imported, placed on the launch pad with collision, and wired to Amber's rocket launch game. Tested end to end.
- **Spitzer Space Telescope:** its file uses **Draco compression**, which Godot can't import (see Phase 1). Its placement and minigame trigger are ready and switch on automatically once an uncompressed file is in place.

## How the minigames are actually triggered (read this first)

Amber's minigame scripts (the `AeroKidz/` code) are **not attached to the rocket or telescope models**.
1. At runtime, `World3DBridge` creates glowing **RoomScreen3D** terminals at fixed positions.
2. Pressing **E** at one calls `BaseMap.EnterRoom(room)`.
3. `LevelController` decides which game opens: Mission 3's **SunWatcherGame** for the Telescope, **RocketLaunchGame** at the very end.

That means deleting or replacing the placeholder models **can't break those scripts**: nothing references them by path. There was one real gap: the rocket had **no 3D trigger at all**. After Mission 3 the launch game started straight away. That's now fixed (Phase 3).

## Phase 1: Import and cleanup

### 1. Put the files in the project

1. Copy the files into **`res://Art/models/`**, next to the other models: in Windows Explorer, `Documents\nasa-space-app-challenge\Art\models\`.
   *(Already done: both files were in that folder.)*
2. Switch to the Godot editor. It imports anything new automatically, and `name.glb.import` files appear.
3. To check an import, double-click the `.glb` in the FileSystem dock to open the **Advanced Import Settings** preview. If the model shows, the import worked.

### 2. If an import fails: the Spitzer file

The Output panel shows:
`glTF: Can't import file 'Spitzer Space Telescope', required extension 'KHR_draco_mesh_compression' is not supported`

The file stores its meshes Draco-compressed, which Godot 4 can't read; no import setting changes that. The original is kept in `Art/models/_source/`, which has a `.gdignore` file so Godot no longer tries to import it.
Get an uncompressed copy with any one of these:
- **Re-download** the model with an option like "glTF (uncompressed)" or "without Draco".
- **Blender, on a PC that allows it:** *File → Import → glTF*, then *File → Export → glTF 2.0 (.glb)* with **Compression unchecked**.
  On this PC, Windows Application Control blocks Blender's Draco module, so this needs another machine or an admin's decision.

Save the result as **`res://Art/models/Spitzer Space Telescope.glb`** (exactly this name), let Godot import it, then do Phase 2 step 4.

### 3. Remove the old rocket and telescope safely

The placeholders are generated by the builder nodes. Deleting them by hand works until the next rebuild, when they come back. So they're **retired**:
- hidden,
- **collision switched off** so you can't bump into an invisible old rocket,
- and remembered, so **Remove Models** can restore them.

| Placeholder | Nodes | Retired by |
|---|---|---|
| Old rocket | `Base/LaunchPad/Lander`, `RocketLander`, `LanderCollision` | Lunar Module entry → *Retire Nodes* |
| Old telescope | `Base/Interiors/Telescope/RingScanner`, `PierCollision`, `Pier`, `Mount`, `OpticalTube`, `Aperture` | Spitzer entry → *Retire Nodes* (applies once the model builds) |

If you'd rather delete a node manually anyway: Scene dock → right-click the node → **Delete Node(s)** → Ctrl+S.
**Before deleting any node, check that nothing references it.** In the Script editor use *Search → Find in Files* for the node's name. For these placeholders there are no references.

## Phase 2: Placement, scale and collision

Both models are entries in **ModelBaseBuilder → Placements** (select the `ModelBaseBuilder` node in `Main.tscn`).

| | Lunar Module | Spitzer Telescope |
|---|---|---|
| File | `apollo_11_lunar_module.glb` | `Spitzer Space Telescope.glb` |
| As imported | 154 × 134 × 154 units; pivot at its vertical center | (not importable yet) |
| **Fit** | **Height = 7.0 m**: the real LM is about 7 m tall, roughly 4× the 1.75 m astronaut, and it fits the 14 m pad | **Height = 3.4 m**, so it fits under the Telescope dome |
| **Position** | (58, 0.2, 32): on the launch pad, outside past the Telescope dome | (36, 0.25, 27.5): where the old instrument stood |
| Pivot fix | Center XZ + Ground Y: the feet sit on the pad | same |
| **Collision** | Box: `StaticBody3D` + `CollisionShape3D` (BoxShape3D), on layers world + camera_blocker | Box |

**1. Tweak the position and size live:** expand the entry and change **Position**, **Rotation Degrees** (Y turns it) or **Scale**. With *Live Update* on, the model moves immediately in the editor.

**2. Collision options:** *Collision* = **Box**, which is cheap and good for big solid props, or **Convex** (one hull per mesh, tighter). Godot's alternative is the import dock: select the `.glb` → Advanced Import Settings → select a mesh → **Physics → Generate: Static Body, Shape: Convex/Trimesh**. That bakes collision into the model's own scene. Use one method or the other, not both.

**3. Doing it fully by hand, without the builder:**
1. Drag the `.glb` from the FileSystem dock into the 3D viewport. This makes an instanced `Node3D`.
2. Set its Transform → **Scale**: for the LM about 0.052, which is 7 ÷ 134; then move it with Position.
3. Add a child **StaticBody3D**, and under it a **CollisionShape3D** with *Shape* = New BoxShape3D. Size the box with the orange handles to cover the model's body.

**4. After any change to an entry** (fit, collision, file), click **Build Models**, then press **Ctrl+S**.
Rebuild order for the whole base: EnvironmentBuilder → SpriteSheetSlicer → ArtReplacer → **ModelBaseBuilder**.

## Phase 3: Reattaching the minigame logic

### The new component: `Scripts/Models/MinigameTrigger3D.cs`

An `Area3D` you put where the player should stand. It forwards to **the same entry point as the room screens**, `BaseMap.EnterRoom(room)` through `World3DBridge`, so Amber's code runs unchanged.

| Inspector field | Meaning |
|---|---|
| **Room** | Which game: `Telescope` = Mission 3 (Sun Watcher), `Rocket` = fly home (Rocket Launch), or Plant / Drill / Oxygen / Power / Shield |
| Prompt | Text shown when near ("" = automatic) |
| Trigger On Enter | Also start when the player just walks in (body_entered) |
| Marker Height | Height of the floating GO HERE marker |

**Two ways to interact:**
- **Press E (default):** it's an `IInteractable` in the `Interactable` group. The team's `PlayerController` shows the prompt within 3 m and calls `Interact()` on E, the same way the room screens work.
- **Walk in:** the `body_entered` and `body_exited` signals are connected **in code** in `_Ready()`, so you don't need to connect anything in the Node dock.
  It's the same as Node dock → *body_entered* → `_on_body_entered`, or in C#: `BodyEntered += OnBodyEntered;`.

### What ModelBaseBuilder generates (from the entry's *Minigame trigger* group)

```
Model_xx_Apollo_11_Lunar_Module__fly_home_ (Node3D)   ← Position / Rotation / Scale
├── Fit (Node3D, auto scale + pivot)
│   ├── Model (apollo_11_lunar_module.glb)
│   └── Collision (StaticBody3D) → Box (CollisionShape3D)
└── MinigameTrigger (Area3D + MinigameTrigger3D, Room = Rocket)   ← at Trigger Offset (−5.2, 0, 0): the ladder
    └── TriggerShape (CollisionShape3D, SphereShape3D r 2.5)
```

The trigger's Collision Layer is 0, so it never blocks movement or the camera; its Mask is 1, so it detects the player.

### Adding a trigger by hand (to any model)

1. Right-click the model → **Add Child Node → Area3D**. Name it `MinigameTrigger`.
2. Inspector → **Script** → Load → `res://Scripts/Models/MinigameTrigger3D.cs`. Set **Room** (e.g. `Telescope`).
3. Under it add a **CollisionShape3D** with *Shape* = New SphereShape3D, Radius about 2. Move it to where the player should stand.
4. On the Area3D set *Collision → Layer* to nothing and *Mask* to layer 1.
5. Ctrl+S. When the game starts, `World3DBridge` finds every node in the `minigame_trigger` group and connects it.

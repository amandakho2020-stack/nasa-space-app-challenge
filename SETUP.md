# Lunar Outpost: Third-Person Graybox (Godot 4.7, C#)

`Main.tscn` already contains everything below, and `project.godot` registers the `GameManager` autoload and the main scene.
Open the project, press **Build** (hammer icon, top right), then **F5**.
Everything is built from Godot primitives: CSG shapes, MultiMesh rocks, primitive meshes, Label3D and procedural noise materials.
The base layout, lunar surface, lighting and rover are generated by the **EnvironmentBuilder** node; see [ENVIRONMENT.md](ENVIRONMENT.md).
The stylized 3D models (rover, geodesic dome, drill rig, rocket, …) are generated in code and swapped in by the **ArtReplacer** node; see [ART.md](ART.md).
The player is a 2.5D billboarded sprite, and the base interior is a starship-style kit (opaque corridors, panelled rooms, curved command console); see [INTERIOR.md](INTERIOR.md).
The final imported models (res://Art/models) are placed by the **ModelBaseBuilder** node; see [MODELS.md](MODELS.md).
Rebuild order: EnvironmentBuilder → SpriteSheetSlicer → ArtReplacer → ModelBaseBuilder, then Ctrl+S.

## Controls

| Input | Action |
|---|---|
| WASD / arrows | Move, relative to the camera |
| Mouse | Orbit the camera around the astronaut |
| Mouse wheel | Zoom the camera (spring arm length 2.5 to 9) |
| Space | Low-gravity jump (1.62 m/s²) |
| E | Interact: airlock door, module consoles, board/exit the lunar rover |
| In the rover | **W** forward, **S** brake → reverse, **A/D** steer left/right, **Space** handbrake, mouse look (camera swings back behind the rover), **E** exit when nearly stopped |
| 1 / 2 / 3 | Equip Scanner / Wrench / Drill |
| 4 | Use an O2 canister (+35 O2) |
| Esc | Free/capture the mouse; also aborts an open minigame |

The input actions are created at runtime by `PlayerController.EnsureInputActions()`, so you don't need to set up the Input Map.

## Game loop

1. You spawn in the **Command Center** (central lobby), facing the monitor bank. The whole base is pressurized: suit O2 doesn't drain and refills at 2/s while the base has power (`GameManager.HubOxygenRefillRate`; set it to 0 for "no drain" only).
2. Go to today's objective. Its console pulses, and the HUD objective shows the distance and compass direction when it's far away (e.g. "(181 m S)"). Signs in the tubes point the way:
   - **West corridor**: Oxygen, Power, Shield
   - **East corridor**: Plant Bio-Dome, Telescope, and the Rover Bay airlock
3. **Drill Site days need the rover.** The drill rig is out on the surface, about 165 m south of the Rover Bay.
   - Go through the Rover Bay airlock and board the rover (E), which is parked facing the road.
   - Follow the marked road south. Its distance signs count down, and an amber beacon marks the site.
   - The rover's life support feeds your suit while you drive, so O2 does not drain. On foot the same trip costs about 35 O2 each way at full speed, and double that after the Sol 2 muscle-atrophy choice.
4. Equip the right tool, then press **E** at the console. The pipe-grid minigame opens on the right.
5. Press **SOLVE**. The game applies the rewards and advances the Sol. On Sols **2, 5, 8** the game pauses and shows the NASA Trade-Off popup.
6. Finish Sol 9 to win. If O2 runs out, HP drains at 5/s; at 0 HP the mission fails. With Power at 0 the base stops protecting you, and O2 drains twice as fast.

| Console | Where | Tool | Rewards |
|---|---|---|---|
| Hydroponics Harvest | Plant Bio-Dome (in base) | Scanner [1] | +30 O2, +1 O2 canister, +5 Science |
| Core Sample Drill | **Drill Site** (remote, outdoors, by rover) | Drill [3] | −10 Power, +25 Science |
| Power Grid Repair | Power Room (in base) | Wrench [2] | +50 Power, +10 Science |

The objective rotates **Plant Bio-Dome → Drill Site → Power Room** each Sol. The Oxygen, Shield and Telescope rooms are built and furnished, but they have no missions yet.
Console rewards, tools and minigame titles are Inspector fields on each `MissionConsole`.

| Sol | Alert | Option A | Option B |
|---|---|---|---|
| 2 | Muscle Atrophy | −50% Move Speed, +50 Science | −25 O2, −15 Power |
| 5 | Regolith Storm | Max Power → 60, +40 Science | −30 O2, O2 drain ×1.25 |
| 8 | Solar Flare | −40 Power, −10 O2 | +75 Science, −35 HP, −20% Move Speed |

## Scene tree (top level)

```
Main (Node3D)
├── WorldEnvironment             → Materials/lunar_environment.tres   (generated)
├── EnvironmentBuilder (Node + EnvironmentBuilder.cs [Tool])  "Build Lunar Environment" button
├── Sun (DirectionalLight3D)
├── LunarSurface                 (generated: regolith, craters, hills, rock MultiMeshes)
├── Player (CharacterBody3D + PlayerController.cs)       spawns in the Command Center
│   ├── CollisionShape3D (CapsuleShape3D r0.35 h1.8)
│   ├── Visual (Node3D, turns to face movement)
│   │   └── Body (CapsuleMesh), Helmet (SphereMesh), Visor (BoxMesh), Backpack (BoxMesh)
│   └── CameraPivot (Node3D, y=1.5, yaw)
│       └── SpringArm3D (pitch, length 5, sphere shape, 0.6 m shoulder offset)
│           └── Camera3D
├── UI (CanvasLayer + UIManager.cs, Process Mode = Always)
│   ├── HUD: StatsPanel (top left), %ObjectiveLabel, %PromptLabel, %MessageLabel,
│   │        %ToolWheel (bottom left), Minimap (bottom right; SubViewport + orthographic camera)
│   ├── %Dimmer, %MinigamePanel (MinigamePanel.cs), %TradeOffPanel, %EndPanel
├── Base                         (generated: shell, rooms, interiors, lights, pressurized zone)
└── LunarRover (VehicleBody3D + RoverController.cs)       (generated, parked in the Rover Bay)
```

The full generated hierarchy is in [ENVIRONMENT.md](ENVIRONMENT.md).
`%Name` means the node has **Access as Unique Name** enabled; UI scripts look nodes up that way.

## Scripts (`Scripts/`)

| File | Role |
|---|---|
| `GameManager.cs` | Autoload. Holds Sol (1–9), HP, O2, Power, Science, the Trade-Off variables (`OxygenDrainRate`, `MaxPower`, …), the inside-base flag, the equipped tool, O2 canisters, the active mission and Mission Elapsed Time. Handles the console → minigame → complete → next Sol → hazard flow, plus win/lose and restart. |
| `PlayerController.cs` | Third-person movement relative to the camera, mouse orbit with yaw/pitch clamps, zoom, low-gravity jump, nearest-interactable detection, tool hotkeys, getting in and out of vehicles. |
| `IInteractable.cs` | Interface: `InteractPosition`, `GetPrompt()`, `Interact()`. |
| `AirlockDoor.cs` | Sliding door with auto-close and indicator light (the Rover Bay airlock). |
| `HubZone.cs` | Area3D that tells the GameManager when the player is inside the pressurized base. |
| `MissionConsole.cs` | Room console: zone, required tool, rewards, minigame title, objective pulse. |
| `LiveScreen.cs` | Label3D screen text with live tokens (`{MET}`, `{O2}`, `{SOL}`, …). |
| `RoverController.cs` | Drivable rover: W forward / S brake-then-reverse / A-D steer (relative to the rover's +Z nose), speed-limited steering, upright stability assist and auto-recovery, recentering chase camera, life support while driving. |
| `UIManager.cs` | Stat bars, diamond tool wheel, minimap follow, minigame hook, Trade-Offs, end screen, mouse-mode handling. |
| `MinigamePanel.cs` / `PipeTile.cs` | Placeholder pipe puzzle. It generates a solvable grid, scrambles it, and lights up connected tiles as you click to rotate. **SOLVE always completes the module** (the prototype hook). |
| `EnvironmentBuilder*.cs` | `[Tool]` generator for the surface, base, lobby, remote Drill Site and road, lighting and rover (6 partial files). |
| `Art/StyleKit.cs`, `Art/MeshKit.cs`, `Art/ModelLibrary*.cs`, `Art/ArtReplacer.cs` | Procedural art kit: palette and materials, mesh builder, 17 models, and the `[Tool]` graybox → model replacer. See ART.md. |

## Swapping in real assets later

- Replace the meshes under `Player/Visual` with your astronaut scene. The movement code only rotates `Visual`.
- Replace room CSG with models: keep (or recreate) the `*Console` nodes, which can be any Node3D-based console that implements `IInteractable`, and the `Base/PressurizedZone` volumes.
- Generated nodes are rebuilt on every builder run. Once you start hand-editing the base, set the builder's **Build Base** to off (or remove the builder node) so it stops overwriting your edits.
- To add real puzzles, replace `MinigamePanel.BuildPuzzle()` and call `GameManager.CompleteActiveMission()` when a puzzle is solved.
